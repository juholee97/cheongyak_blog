# 3단계 설계 — "이번 주 청약 일정" 글 초안 → 티스토리 임시저장

## 목표
매주 한 편, `schedule.json`만으로 "이번 주 청약 일정" 글을 만들고, 사람이 채팅에서 승인하면 티스토리에 **임시저장**까지 한다. 발행은 사람이 직접 한다.

## 지켜야 할 것 (CLAUDE.md 절대 규칙과 같음)
- 글의 날짜·세대수·분양가·단지명은 전부 `schedule.json` 값이다. 없는 값은 쓰지 않는다(추정 금지).
- 투자 권유 표현 금지("추천", "로또", "무조건", "오른다" 등). 글 끝 면책 문구는 빼지 않는다.
- 출처(청약홈·공공데이터포털)와 기준일시(`updatedAt`)를 글에 적는다.
- 자동화는 임시저장까지. 발행 버튼은 가드로 막는다.
- 티스토리 로그인은 사람이 직접 한다. 세션 폴더는 커밋하지 않는다.
- AI 작업은 Claude Code 세션 안에서만(API 키 없음).

## 전체 흐름
```
[1] 생성   node posts/weekly.mjs --week 2026-10-26
           schedule.json(Pages) → drafts/2026-10-26_weekly.json(제목·태그·카테고리·본문 HTML)
                                 + drafts/2026-10-26_weekly.html(미리보기)
[2] 요약   Claude 세션이 글머리 요약 2~3줄을 쓴다(사실만, 숫자는 [1]의 집계값 그대로)
[3] 검수   node posts/check.mjs drafts/2026-10-26_weekly.json
           · 본문의 모든 날짜·숫자·단지명이 schedule.json에 있는지 대조
           · 금지 표현, 필수 문구(출처·기준일시·면책) 확인
[4] 승인   채팅에서 미리보기(PC·휴대폰 폭)를 보여 주고 사용자 승인을 받는다
[5] 저장   node tistory/draft.mjs drafts/2026-10-26_weekly.json
           새 글 화면 → 발행 가드 주입 → HTML 모드 → 제목·카테고리·태그·본문 → 임시저장
[6] 검증   임시저장 글을 다시 열어 본문 텍스트를 [1]과 전문 대조 + 스크린샷
[7] 발행   사람이 티스토리에서 확인 후 직접 발행
```

## 1. 이번 주의 범위
- 기본: 실행한 날이 속한 주의 **다음 월요일 ~ 일요일**(일요일 저녁에 만들어 월요일 아침에 발행하는 흐름). `--week`로 시작 월요일을 직접 줄 수도 있다.
- 실제 데이터로 재 보면(10월 26일 ~ 11월 1일) 일정이 있는 단지 28곳, 접수 시작 12곳, 당첨발표 18건, 계약 7건이다. 글 한 편으로 충분한 분량이다.

## 2. 글 구성
**제목**: `이번 주 청약 일정 (10월 26일~11월 1일) | 접수 12곳·발표 18곳` — 28~40자, 숫자는 집계값.

**카테고리**: 청약일정 · **태그**: 청약일정, 이번주청약, 아파트청약 + 등장한 종류(무순위·오피스텔 등) + 접수 단지가 있는 시·도(서울청약, 경기청약…), 최대 10개.

**본문**(티스토리 HTML 모드에 넣을 단순 HTML: h2·h3·p·table·ul, 인라인 스타일 최소)
1. 요약 박스 — 기간, 접수 시작 N곳(특별공급·1순위·무순위 등 종류별), 당첨발표 N곳, 계약 N곳, 기준일시·출처. Claude가 쓰는 2~3줄 요약도 여기.
2. **이번 주 접수 단지 표** — 접수일 | 단지명 | 지역 | 종류 | 공급 세대. 날짜순.
3. **접수 단지별 상세**(h3 하나씩) — 위치, 종류, 공급 세대, 분양가(3.3㎡, 있을 때만 + "최고분양가 기준" 주석), 단계별 날짜 표, 청약홈 공고 링크.
4. **이번 주 당첨발표 · 계약** — 날짜별 짧은 목록(단지명 · 지역).
5. 전체 달력 안내 — "지역·자치구별로 보려면 블로그 홈 달력" 링크.
6. 면책 — "청약 일정은 입주자모집공고 기준이며 사업주체 사정에 따라 변경될 수 있습니다. 신청 전 반드시 청약홈의 입주자모집공고를 확인하세요."

**썸네일**: 1차는 없이 시작. 2차에 "10월 4주차 청약 일정" 카드 그림을 HTML→PNG로 만들어 첫 이미지로 넣는다(티스토리는 첫 이미지를 대표 이미지로 쓴다).

## 3. 데이터 보강 (fetch.mjs)
지금 `schedule.json`은 단계별 **시작일만** 있다. 글에는 접수 기간이 필요하다.
- 단계에 `end`(종료일)를 더한다: 특공·청약접수·계약은 API에 종료일이 있다. 1·2순위는 해당지역 시작일 기준이라 `end` 없이 둔다.
- `noticeDate`(모집공고일)를 더한다: "이번 주 새로 나온 공고" 묶음과 정렬에 쓴다.
- 기존 키는 그대로 두므로 달력은 영향 없다. `check.mjs`에 매핑 테스트를 추가한다.

## 4. 티스토리 임시저장 자동화
- **공식 API는 못 쓴다.** 티스토리 Open API 글쓰기는 2024년 말 중단된 것으로 알려져 있다(공식 공지는 미확인). → Playwright로 글쓰기 화면을 조작한다(네이버 하네스와 같은 방식).
- **로그인**: `tistory_login.bat` → 전용 브라우저 프로필(`data/tistory-session/`, .gitignore)이 열리면 사용자가 카카오 로그인. 이후 세션 재사용.
- **글쓰기 화면**: `https://aulee.tistory.com/manage/newpost/`
  1. 발행 가드 주입 — "완료" 뒤 발행 레이어의 발행 버튼 클릭을 캡처 단계에서 막는다(blogging_ai `installPublishGuard`와 같은 구조, 셀렉터만 티스토리용).
  2. 에디터를 **HTML 모드**로 전환해 본문 HTML을 넣는다(티스토리 에디터는 기본모드·마크다운·HTML 전환이 있다).
  3. 제목, 카테고리(청약일정), 태그 입력.
  4. **임시저장** 클릭 → 저장 알림 확인.
- **셀렉터는 추측하지 않는다**: 먼저 `tistory/probe.mjs`로 실제 화면의 버튼·입력칸을 실측해 `tistory/selectors.json`에 적는다.
- **검증**: 임시저장 글 목록에서 방금 글을 다시 열어 본문 텍스트를 생성본과 전문 대조. 다르면 실패로 보고하고 저장 글은 지우지 않는다(사람이 정리).
- 운영: 본인 계정, 주 1회. 자동화는 약관상 회색지대라 "초안 공장"으로만 쓴다.

## 5. 만들 파일
| 파일 | 역할 |
|---|---|
| `posts/weekly.mjs` | schedule.json → 초안 JSON + 미리보기 HTML (순수 함수 + `--self-test`) |
| `posts/check.mjs` | 사실 대조·금지 표현·필수 문구 검수 |
| `tistory/login.mjs`, `tistory_login.bat` | 사용자 로그인용 브라우저 열기 |
| `tistory/probe.mjs` | 글쓰기 화면 셀렉터 실측 |
| `tistory/draft.mjs` | 임시저장 + 발행 가드 + 전문 대조 검증 |
| `weekly_post.bat` | 실행기(생성 → 검수 → 미리보기 열기), 바로가기 `D:\AI_산출물` |
| `.claude/skills/weekly-post/SKILL.md` | Claude 세션 절차(1~7단계, 승인 없이는 저장 안 함) |

## 6. 구현 순서
1. fetch.mjs 보강(`end`, `noticeDate`) → Actions 재실행 → schedule.json 확인
2. `weekly.mjs` + `check.mjs` + 미리보기 → 실제 데이터로 초안 1편, 사용자 검토
3. 티스토리 로그인 → probe로 셀렉터 실측
4. `draft.mjs`로 첫 임시저장 + 검증 → 사용자가 직접 발행
5. 썸네일 카드(2차)

## 7. 정해 주실 것 (기본값으로 진행 가능)
- 주 범위·작성 시점: **다음 주 월~일, 일요일 저녁 작성** (기본)
- 지역 범위: **전국 한 편** (서울만 따로 쓰는 글은 나중에)
- 요약 문장: **템플릿 + Claude가 쓰는 2~3줄** (숫자는 집계값만)
- 분양가 표기: **있는 단지만, "최고분양가 기준 평균(공급면적 3.3㎡)" 주석과 함께**
