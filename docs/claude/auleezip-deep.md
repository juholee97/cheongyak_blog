# 우리의 집 심층 분석 글 만들기 (`zip/deep.mjs`)

심층 분석 글을 쓰거나 고치거나, 감시 예약 작업(`auleezip-deep-report-watch`)을 손볼 때 읽는다. **글 쓰는 기준(순서·시선·제목·가독성·그림)은 `docs/deep-writing-guide.md`가 원본**이고, 이 파일은 흐름·도구·검수 규칙이다. 사이트 운영은 `auleezip.md`. 괄호 안 날짜로 `history.md` 검색.

## 흐름
1. **대상 고르기** `zip/deep_targets.mjs`(매일 `--make`): 매매 청약(APT·무순위·임의공급) 중 수도권 또는 지방 핵심지(`CORE`: 세종, 부산 해운대·수영·동래·남·연제, 대구 수성, 대전 유성·서, 광주 남·서, 울산 남, 창원 성산·의창, 천안 서북), 첫 접수가 3일 이상 남은 곳. 임대는 수도권 청년안심주택(youth-*)과 LH 행복주택(lh-*)만(`isRent` — 매입·전세임대·예비입주자·자격완화 상시모집·기관 대상 제외. 공공지원 민간임대·국민·영구·공공임대·SH 사회주택은 넣지 않는다). 분석기 폴더 `D:\부동산_청약분석\<단지>`와 `data/deep_folders.json`을 만든다.
2. **분석기 리포트**: 유튜브 분석기(`D:\dev\apt_youtube_analyzer`, 폴더 감시 — 단지당 30분~1시간, 60일 동안 3일마다 갱신)가 영상·공고문·공식 자료로 `종합리포트.html`을 만든다. 직접 처음부터 쓰지 않고 이 리포트를 바탕으로 쓴다(2026-10-30 사용자).
3. `node zip/deep.mjs --read <키>` — 리포트 글자(가족 맞춤 절·우리집_정보는 빠짐). 리포트가 바뀌면 이전 글자를 `<키>.prev.txt`로 남긴다.
4. 글 자료 `data/zip_deep/<키>.json` 작성(v2, 합쇼체). 시군구 시장은 먼저 `node zip/market.mjs <시군구코드>`.
5. `--lint` → `--preview`(로컬 화면) → `--draft`/`--publish`(카테고리 「심층 분석」, 안쪽 이름 `deep-<키>`·주소는 자료의 `slug`, 대표 이미지 = 조감도). 공개 시점은 `auleezip.md`의 「공개 시점」.
6. 올리기 전·공개 뒤 검수가 자동으로 돈다(실패면 종료 코드 1). 언제든 `node zip/deep.mjs --verify <키>|all`.
7. 조감도가 `zip_views.json`에 `tried`뿐이면 공식 출처에서 받아 `views.mjs --add`(→ `auleezip.md` 「조감도」).
8. 구글 색인 요청은 감시 예약 작업이 한다(→ `seo-analytics.md`).

키: 청약홈은 공고번호, LH는 `lh-<id>`, 청년안심주택은 `youth-<id>`(`deep_targets.mjs` `noOf`와 같음).

주소(2026-11-16): 워드프레스 주소는 자료의 `slug`(한글 키워드, 규칙은 안내서 3-2), 안쪽 이름은 `deep-<키>` 그대로다(저장 표시 `post:deep-<키>`·단계 장부·색인 장부·로그). `wp.mjs upsert`는 저장 표시의 id → `slug` → `deep-<키>` 순으로 글을 찾고 `slug`를 보낸 뒤 돌아온 주소가 같은지 본다(겹쳐 `-2`가 붙으면 실패). 공개된 글의 주소를 바꾸면 워드프레스가 옛 주소를 301로 넘긴다. 달력 링크 목록(`crawler/auleezip_links.json`)은 글의 지금 주소(새 한글 주소)를 적는다 — 2026-11-16 티스토리 스킨이 한글 주소를 받게 되어(7fc7470) `publish.mjs` `LINKS_OLD_FORM`을 false로 했다(스킨이 다시 옛 꼴만 받게 되면 true, 그때는 옛 꼴 `deep-<키>`). 문장 속 다른 글 링크는 `[[l:보이는 글자|키]]`.

## 사실 확인 — 공고문이 기준
- 리포트 숫자가 공고문과 다르면 공고문대로 쓴다. 리포트는 영상·보도·지난 회차 기준일 때가 많다(전매제한 기간, 계약일, 주택형, 소득 기준, 주차 대수, 금액 자릿수 오독 사례 다수).
- 분석기 폴더에 공고문이 없거나 그림 PDF면, 청약홈·LH 청약플러스·서울시 누리집의 공고문 PDF 글자를 `data/notice_text/<키>.json`에 옮겨 적고 그 숫자로 쓴다(PyMuPDF는 `tools/ocr_venv`). `--lint`가 이 파일을 근거로 인정한다.
- 출처가 엇갈려 확정 못 하는 숫자는 확정하지 않고 「공고문 확인」·「확인 필요」로 쓴다. 공고문에 없는 안내(입주지원금 등)는 서면 확인으로.
- 청약홈 일정의 첫 접수가 사전청약 당첨자 몫인 공고가 있다 → `receipt`에 실제 첫 접수일.
- 토지임대부는 시세 비교를 참고로만 쓰고 토지임대료와 「차익으로 볼 수 없다」를 함께. 준공 단지 무순위는 옵션 승계 총액과 그 단지 실거래를 함께 적어 분양가만의 「N% 낮음」이 차익으로 읽히지 않게.
- 시세가 높게 나온 단지는 비교 단지의 연식·평형 차이 같은 확인되는 사정을 함께 적는다. 이유를 지어내지 않는다.
- 개인(임대사업자) 이름은 글에서 뺀다.

## 출처 매체를 밝히지 않는다 (2026-10-30 사용자 결정)
- 채널·영상 이름·링크·재생 시각을 쓰지 않는다(특정인을 깎아내린다는 다툼 방지). 「온라인에 공개된 여러 분석 의견을 공고문과 맞춰 봤다」는 자리에서 포괄해 쓴다. 채널 신뢰도 평가도 옮기지 않는다.
- `scrub`이 리포트 문장의 영상 번호·채널 이름·재생 시점·내부 파일 이름(`notice…` → 「공고문」)을 지우고 조사를 맞춘다. `chNames`는 괄호 앞 이름도 잡는다. `--lint`가 유튜브·영상·채널·출연자·자막·조회수 흔적을 잡는다.
- 가족 맞춤 문장(「우리 부부」·「아기 계획」·「우리 아이가 배정된다」 등)은 `FAMILY`·`scrub`이 걸러낸다.
- 본문에 작업 파일 경로(`docs/policy/loans.md` 등)를 쓰지 않는다 — 공식 출처 이름으로(`PATH_RE`, 2026-11-12).
- 금지 표현(`BANNED`): 「확실」→「분명」, 「시세차익」→「차익」, 「오를 수」→「인상될 수」. 공식 제도 이름 「수익공유(형)」·기관추천은 예외.

## 글 자료 블록
- 기본: `h` `p` `ul` `key` `table`(`compact`) `note` `src` `links` `claims` `grid` `plan` `view` `timeline`(`schedule`·`money`·`bars`·`trend`) `calc`.
- v2(2026-11-02): `take` `signals` `two` `who`. 문단 230자 이하.
- `grid`는 단지가 하나면 쓰지 않고 [항목, 내용] `table`. `plan`은 [구분, 내용, 상태](확정·계획·공고문 색 표시). 노선 이름(`LINES`)은 노선 색 표시.
- `timeline`(`zip/timeline.mjs`): Playwright로 2배 해상도 PNG, alt에 일정·금액 전부. 붙어 있는 회차는 막대 하나로 합친다. 회차가 두 번뿐이거나 날짜가 처음·끝만 있으면 그림 대신 표.
- `calc`(보이는 금액, 만원 단위 식): 식의 바탕 숫자가 자료에 있고 계산이 맞으면 계산값도 lint 통과.
- 색 표시: `[[r:글귀]]` 위험, `[[y:]]` 주의, `[[g:]]` 유리, `[[b:]]` 핵심 숫자(글 전체 몇 곳). 한 항목에 한두 곳 짧은 글귀로, 칠한 글자는 굵게 하지 않는다. 당연한 권유·덜 중요한 것은 칠하지 않는다.
- 첫 소제목 바로 밑에 조감도가 자동으로 들어간다(`data/zip_views/{키}.jpg`, 2026-11-10).
- 글 맨 위 한 줄(`az-src`) + 글 끝 「이 글의 자료」(사용자 문안 그대로, 2026-11-09). 공고 기준일·공고 원문 링크 필수.
- `added`(공고문 대비 추가 정보)가 없으면 새 글은 lint가 막는다.
- 가격 표현: 「주변 단지 실거래가와 직접 비교한 결과, …」(「우리의 집 비교로는」 금지, 2026-10-31).
- 임대 글: 시세 비교 글이 없으므로 가격 절은 「들어갈 때 필요한 현금」(보증금 vs 주변 전세 실거래)과 보증금 비율 전환으로. 본보기 youth-6718·6719.

## 분석 의견 대조표 (`claims`)
- 리포트 `summary.json` claim_checks에서 자동. 절 이름 「공개된 분석 의견」, 대조표는 그 아래 「공고문과 맞춰 본 결과」.
- 공고문과 다른 것 먼저. 맞는 주장은 `claims.keep`에 적은 것만 싣는다(다른 절과 겹치는 당연한 내용 제외).
- 이름·표기만 틀린 주장(오인식·오타)은 「다름」으로 싣지 않는다(`TYPO`·`NAME`). 금액이 걸린 주장은 남긴다. 가격 전망·가족 문장은 제외.
- 리포트의 틀린 줄을 그대로 옮기게 되면 대조표를 뺀다.

## 제목·카드 문구
- 제목 규칙은 안내서 3-1(단지명 → 유형 → 사실 → 「심층 분석」, 무순위는 「무순위 청약(줍줍)」). `titleIssues`가 새 글(link 없는 글)만 점검. 이미 올라간 글 제목은 그대로 — 2026-11-13 제목 시험 13편은 사용자가 승인한 예외(`docs/title-test-20261113.md`).
- 카드 `hook`: [작은 줄, 큰 줄, 노란 줄]. 맨 위 노란 이름표(hook[0])는 단지 이름이 아니라 핵심 매력 한 마디(「GTX-A 초역세권」) — 서술형 금지.
- 문구 원칙(2026-10-31 사용자 반복 피드백): 사는 사람이 얻는 것을 앞에, 사실만. 「높다?」 같은 부정 끝맺음, 「예정」·「계약 때」 같은 서류 말투 금지. 「이유는?」을 쓰면 글에 이유가 있어야 한다. 가격은 주변보다 아주 쌀 때만 내세우고 나머지는 생활 이득으로. 숫자 나열은 지루하다. 사실이 아니면 쓰지 않는다(역세권·조망 등).

## 청약 결과 추적 (2026-11-11)
- 청약홈 경쟁률 공개 자료(odcloud ApplyhomeInfoCmpetRtSvc, guard datago)를 `deep.mjs updateResults`가 받아 `data/zip_results.json`에. 매일 `publish.mjs --go` 끝 + 감시 예약 작업 0b(`--results`).
- **결과로 공개 글을 다시 저장하지 않는다**(2026-11-17 주인 결정, `deep.mjs` `RESULT_REPUBLISH_HOLD = true` — 풀기는 주인 결정 뒤에만). 결과 자료는 계속 쌓고, 보이는 표가 바뀐 글은 반영 대기 `data/zip_results_pending.json`(키 → 처음 바뀐 날)에 적는다. 풀면 대기 글을 한 편씩 `--publish --urgent`(한 편 실패해도 계속, 성공한 키만 지움 → 실패한 글은 다음 실행이 다시) — 하루 수정 한도 밖이라 풀기 전에 대기 수를 본다.
- 이미 결과 절이 들어간 공개 글은 그대로 그려진다(글 맨 위 「청약 결과」 절).
- **「청약 결과 모음」 고정 페이지** `/results/`(`pages.mjs resultsPage`, 재료 `deep.mjs resultPosts`·`resultStats`·`resultBlocks`): 요약 표(최신 결과순, 공개된 심층 분석 글만 링크) + 글별 상세(`id="r-<키>"`). 기준일은 결과 자료의 가장 늦은 날이라 결과가 그대로면 페이지도 안 바뀐다. `publish.mjs --go`가 `updateResults` 뒤에 올린다 — `RESULTS_PAGE_LIVE`(`deep.mjs`, `publish.mjs`가 다시 내보냄)가 `true`일 때만. 지금 `false`(미리보기 `preview/results_20261117/` 승인 대기).
- 새 글 링크: `RESULTS_PAGE_LIVE`가 켜져 있고 아직 공개된 적 없는 글(`liveDeep` 거짓 — 초안·예약 시각 전)은 결과 절 대신 맨 위 출처 줄 밑에 「청약 결과(경쟁률)는 접수가 끝난 뒤 청약 결과 모음에서 볼 수 있습니다」 한 줄(`/results/#r-<키>`). `--draft`/`--publish`가 자료에 `resultsLink: true`를 남겨 공개 뒤에도 같은 HTML(`resultsLinkOf`). 이미 공개된 글은 스위치를 켜도 HTML이 한 글자도 안 바뀐다(2026-11-17 전 글 57편 렌더 해시로 확인).
